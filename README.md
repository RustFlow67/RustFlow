# SHIFT — веб-витрина и исходники Windows-приложения

Публичный сайт теперь состоит из четырёх сцен и не содержит веб-инструментов.
Маршруты `/benchmark`, `/presets` и `/tweaker` удалены из веб-версии; исходники
настольного интерфейса сохранены отдельно в `desktop-src/`. Подробнее о запуске,
сборке и публикации установщика: [docs/showcase.md](docs/showcase.md).

```bash
npm ci
npm run dev
npm run lint && npm run typecheck && npm run build
npx playwright install chromium
npm run test:ui
npm run build:desktop
```

Windows-установщик не включён; desktop-сборка создаёт статические ресурсы, а
нативную упаковку и поведение необходимо проверять на Windows. Исторические тесты
`npm run test:legacy` и документация ниже описывают прежний интерфейс, а не текущий сайт.

## Архив: документация прежнего интерфейса

# RustFlow — настройка Rust и сравнение сборок

- **Главная**: три шага от ввода комплектующих до конфига и обратимых твиков, автоподбор по конфигурации и живая консоль.
- **С чего начать** (`/guide`): пять шагов с локальными отметками прогресса. Старые ссылки на статьи ведут к их новым разделам.
- **Сборка** (`/benchmark`): одна стеклянная панель с вводом ПК и результатом, на телефоне — одна колонка. Три основных режима графики; «Реалистичность», тайминги и параметры сессии доступны в дополнительных настройках. На FPS и 1% low влияют сценарий (фарм, PvP или клан-рейд), режим задержки, фоновые приложения, буфер GC и настройка рендера/теней. Результаты MODDED 2X / OFFICIAL HIGH POP — оценки, не игровые замеры. Из отдельного предпросмотра можно скачать именно показанный `client.cfg`. Радар CPU/RAM/SSD/GPU/VRAM, средний FPS и 1% low пересчитываются по той же модели.
- **Пресеты** (`/presets`): 43 конфигурации, сравнение до трёх, графика для всех или отдельной карточки, 4:3 и свои размеры кадра. Готовый `client.cfg` скачивается прямо с карточки или из деталей, без входа; разрешение выставляется в игре. Пресеты и калькулятор используют одну модель; исходная точка — нативные 1080p, «Комбат», «Фарм / Берег», без генерации кадров. Результаты — оценки, не замеры.
- **Твикер** (`/tweaker`): шесть категорий, NVIDIA/AMD/Intel и четыре профиля. Подбор учитывает VRAM, ОЗУ и накопитель. В просмотр и в ZIP передаются параметры сессии; для Radeon Anti-Lag настройка драйвера описана в README архива. Старые сохранения с лимитом `fps.limit` остаются читаемыми. Профиль сети справочный: сетевые команды в конфиг не записываются. ZIP содержит только выбранные допустимые шаги, `client.cfg` и откат. «Все твики» открывает список, но не применяет и не добавляет шаги автоматически.
- **Драйверы** (`/drivers`): пять кнопок открывают выбор серии и модели. Для GPU указаны примеры совместимых выпусков, страницы производителей и OEM, выбор между обычной и чистой установкой.
- **Система Windows** — вторая вкладка Твикера (`/tweaker?tab=windows`; старые ссылки `/windows#…` сохраняют раздел): настройки 10/11, протокол повторяемого замера, защита и фоновые задачи.
- **Мифы и EAC** (`/faq`): рискованные советы, плацебо, безопасные альтернативы и восстановление.
- **ИИ-ассистент**: чат из отдельной круглой кнопки с искрами справа от шестерёнки. В Dock пять разделов: Главная, Сборка, Пресеты, Твикер и Драйверы. Ключ провайдера нужен только на сервере.

**Веб и настольная оболочка.** По умолчанию `IS_DESKTOP_APP` в `src/lib/config.ts` равен `false`: работают ZIP с откатом, буфер обмена, скачивание `client.cfg` и ссылки производителей/DDU. Для сборки настольного интерфейса задайте `NEXT_PUBLIC_IS_DESKTOP_APP=true` **при сборке**. Компонент `AdaptiveActions` вместо этих кнопок передаёт выбранный конфиг, шаги или модель устройства в `src/services/systemBridge.ts`. Переход по URL не переключает платформу.

Это контракт для будущего Tauri/Electron, не установщик. Оболочка предоставляет `window.rustflowSystem`: поиск папки Rust, бэкап `client.cfg`, чтение железа и ОС, обратимое применение/откат и чистая установка драйвера. Она должна проверить устройство и разрешённые изменения, получить согласие и сохранить исходное состояние до записи. Без модуля операции возвращают `unavailable` и не меняют ПК. Явно выбранная версия Windows имеет приоритет над данными модуля; если версия неизвестна, настольный автоподбор не рисует плашку и не добавляет шаги для конкретной версии. Проверки интерфейса: `npm run test:ui` (веб, порт 3000) и `NEXT_PUBLIC_IS_DESKTOP_APP=true npm run test:ui` (настольный режим, порт 3001, без реальных установок).

**Поиск и сортировка.** В Твикере и внутри категорий приоритет пользы, оценка среднего FPS, безопасность и избранное — разные режимы. Значение `gc.buffer` показывается из текущего профиля, второй установщик в ZIP не добавляется. В Пресетах доступна сортировка по открытым деталям, сходству CPU/GPU/RAM с активной сборкой, верхней границе FPS и избранному. Тематические библиотеки ищут также по командам и пояснениям. Для «Популярных» `/api/catalog` считает явные открытия (повтор в той же вкладке не учитывается), а не показы и не поисковые запросы. С PostgreSQL счётчики хранятся в `rf_catalog_views` (`npm run db:push`), без него — в памяти до перезапуска. При равенстве используется редакционный порядок.

**Стекло и шрифт.** Карточки, капсулы шапки, Dock и линзы используют компонент `LiquidGlass` без дополнительной DOM-обёртки: по умолчанию `blur(28px) saturate(165%)`, зеркальная кромка и преломление без дисперсии. В Chromium общие Canvas-карты кромок и SVG `feDisplacementMap` переносят весь цвет пикселя. У Safari/Firefox нативная оптика по умолчанию `blur(16px) saturate(1.7) brightness(1.08)` и тот же зеркальный блик. Цвет стекла и обоев следует выбранному материалу; «Полный Liquid» ахроматичен. Используется локальный вариативный Inter для текста и кнопок. Заголовки — кириллический Unbounded 700/800/900 через `next/font/google`. Штатные `npm run dev` и `npm run build` используют webpack и локальные OFL-файлы этого же шрифта: Google не нужен ни сборочному серверу, ни браузеру. Для обычной загрузки шрифта при сборке: `RUSTFLOW_FONT_SOURCE=google npm run build`. Lite отключает дорогие фильтры и движения; у экранного периметра нет ни цвета, ни свечения.

**Вердикт по апгрейду** сравнивает ровно одно изменение в трёх сценах Official при том же разрешении. В форме предлагаются 15 моделей AM4/AM5/LGA1700; предыдущие сохранения и пресеты остаются читаемыми. Для CPU рассматриваются только кандидаты из этого набора под его сокет; модель не знает модель платы, БП или кулера. Альтернативы ранжируются по классу затрат и прогнозу, не по рыночным ценам. 0.1% low и длительность длинного кадра — оценки по 1% low, накопителю, свободной RAM и нагрузке на VRAM, не замеры. Если заметного выигрыша нет, матрица не обещает прироста.

**Rust F1 Console и Frame Time.** На главной F1 показывает пример диалога клиента: `Writing...` во время набора, `Verified` и ответ после строки. Наведение, фокус на команде или кнопка паузы останавливают вывод; буфер обмена получает только текст выбранной команды. График у автоподбора на главной и в «Пресетах» иллюстрирует ритм кадров, а не измеряет ПК или запущенную игру. За пределами экрана и в скрытой вкладке оба виджета не проигрываются.

**Живые обои.** BlobWallpaper рисует два автономных 2D-поля: шесть цветных и пять прозрачных капель соединяются и расходятся, не следуя за мышью. Градиент и стекло используют палитру Студии. В «Полном Liquid» нет цветной примеси. Без WebGL Canvas2D строит контуры тех же полей; Lite, уменьшенное движение, «Киберспорт» и «Статичный фон» не запускают цикл анимации. В скрытой вкладке часы остановлены.

**Карточки и навигация.** На шести карточках принципов только кнопка «Подробнее ↗» открывает пример. То же правило действует в статьях и «Мифы и EAC»; ссылки на инструкции и FAQ-аккордеоны работают независимо. Окно разворачивается из нажатой кнопки за 440 мс и возвращается к её текущим границам за 420 мс. Размытие исчезает к последней пятой геометрического пути обратно. На оставшихся 20% оболочка плавно становится прозрачной, не перекрывая исходную кнопку при посадке. Кнопка остаётся на месте и слегка отскакивает после посадки. Содержимое карточки остаётся в DOM; у прокручиваемого окна свой внутренний скролл, а кромка остаётся на месте. Повторный клик по активной вкладке прокручивает страницу вверх. Пока открыто окно, Dock отступает, остальные кнопки шапки скрыты; Escape возвращает управление источнику. При прокрутке вниз после 15 px шапка и нижний Dock приближаются до 103,5% с мягким свечением темы. Прозрачные полосы под ними плавно усиливают размытие с 8 до 16 px и сходят на нет к центру экрана. Первое движение вверх возвращает панели в исходное положение за 360 мс, даже в середине страницы. Для бокового Dock нижняя полоса не рисуется. При наведении в Dock, меню и переключателях стеклянное выделение меняет положение и размер за 480 мс, не выбирая пункт. При уходе курсора оно возвращается к активному пункту; в мгновенном режиме задержки нет. При смене вкладки слегка двигаются только капсулы и иконки. Кромки, шкалы и акценты берут цвет из выбранного материала; белой бегущей полосы нет.

**Подбор по сборке.** Из верхней кнопки «Посмотреть ИИ-сводку» в «Сборке» и автоподбора на главной можно открыть ближайший реальный пресет или перейти к отмеченному пакету твиков. Учитываются CPU, GPU, экран, RAM, диск и выбранная версия Windows. Это локальное объяснение рассчитанных баллов, ограничений и шагов, а не ответ внешней языковой модели. Неизвестную версию Windows сайт не угадывает. Буфер GC входит одной строкой в client.cfg, а шаги Windows и драйвера можно проверить в README скачанного ZIP. В Твикере сводка объясняет именно выбранные шаги пакета, их риски, перезагрузку и откат. Применимые действия отделены от справки: отключение HVCI/Defender, очистка standby-памяти, форсирование IRQ и другие спорные советы не доступны для ZIP. Предпросмотр не применяет настройки на ПК. В библиотеке 93 позиции, из них 60 могут входить в ZIP; набор для конкретного ПК уже и зависит от GPU и ОС. Открытая страница `/files/<slug>` показывает фактический файл. Для REG доступны BAT-снимок отдельных значений перед применением и восстановление этих значений (или их отсутствия). В ZIP они лежат в `Do-REG/` и `Otkat/`. Возврат к типовым значениям не равен восстановлению снимка.

**Окна шапки** открываются на 10 px ниже нажатой кнопки: меню RustFlow, настройки и чат выровнены по её левому краю, профиль — по правому. На узком экране сужается само окно, а не меняется точка привязки. Иконка затихает за 80 мс. Тот же стеклянный элемент переходит из кнопки в окно: меняет положение, ширину, высоту и скругление за 420 мс; фон размыт на 12 px. При закрытии текст гаснет за 140 мс, стекло сжимается за 380 мс, а на последней пятой пути возвращается иконка, без второй матовой поверхности. Выбор раздела завершает обратный перелёт к логотипу до перехода на главную, в «С чего начать», «Мифы и EAC» или открытия справки FAQ / «О нас». Шестерёнка справа открывает «Настройки»: библиотеку десяти материалов, оптику стекла, обои и положение Dock. Нижний Dock с отступом 4 px показывает подписи, левый — компактные иконки с подсказками. Сохранённое положение «сверху» мигрирует в нижнее до первого кадра. Верхние капсулы высотой 54 px, шестерёнка 54×54 px и боковой Dock шириной 54 px. Все пять нижних вкладок помещаются в ряд даже при ширине 320 px; при нехватке места прокручивается сама капсула. Положение запоминается на устройстве без входа. Янтарь, перламутр, рубин, изумруд, «Оригинальные цвета Rust» и «Полный Liquid (Чистое стекло)» доступны гостям. После входа открываются лёд, аметист, обсидиан и золото. Гость может примерить настройки до перезагрузки; для профиля также доступен вход из меню тем. Студия меняет оптику, режим анимации и движение обоев без перезагрузки. VIP-выбор и настройки хранятся отдельно для каждого профиля в этом браузере; при выходе возвращается публичная тема. Режим движения учитывает системное уменьшение анимаций; частота кадров зависит от устройства.

Сайт работает и без регистрации. Локальные сборки, отметки и выбор пакета остаются в браузере. В «Профиле» можно создать аккаунт и явно привязать активную локальную сборку; «Настроить в Сборке ↗» откроет сохранённую в аккаунте конфигурацию на другом устройстве. Из неё можно сделать локальную копию для бэкапа или повторного открытия на этом устройстве. Данные браузера не перезаписываются при входе. Без сервера аккаунтов форма работает с профилем на этом устройстве, без синхронизации и серверных прав.

Для игрового диска модель различает HDD 7200 RPM, SATA SSD и NVMe PCIe 3.0/4.0/5.0. Буфер (DRAM, HMB только у NVMe, без буфера) и заполненность диска меняют диапазон Asset Warmup и оценку длинных кадров при подгрузке, а не среднюю скорость рендера. В старых записях `hdd`/`sata`/`nvme` остаются валидными; без уточнений расчёт предполагает Gen3 для NVMe, DRAM для SSD и занято менее 70%. Это модель, а не измерение диска пользователя.

Калькулятор автоматически сохраняет каждое корректное изменение в текущую сборку в localStorage, без входа и без кнопки сохранения. Незаконченный ввод не затирает последнее корректное значение. Ручная частота DDR4 — 2133–5333 МТ/с, DDR5 — 4800–9600 МТ/с. Для собственного разрешения ширина ограничена 800–7680 px, высота — 600–4320 px. Подготовить подборку можно без входа. Привязка локальной сборки к аккаунту, JSON и скачивание ZIP доступны через «Профиль игрока». Кабинет открывается под правой капсулой. Никнейм, аватар, тег Discord/Steam и счётчики сохраняются по идентификатору профиля в этом браузере. Расчётный прирост сравнивает текущий графический профиль с «Качеством» в одной сцене, уровень оптимизации — доля отмеченных рекомендаций. Резервная копия с экспортом и импортом JSON — отдельное вторичное действие. JSON не содержит данных входа или истории чата и не перезаписывает сборку в аккаунте.

`/api/pack` проверяет облачную сессию. При входе в локальный профиль ZIP с теми же настройками и откатом собирается в браузере, без выдачи серверной сессии. Локальный вход не обеспечивает изоляцию данных между пользователями одного браузера. В архиве нет `.exe`.

Сетевые команды `lerp.*` и экспериментальный лимит mipmap больше не добавляются в конфиг: проверьте настройки сети и текстур в самой игре. Сохраните `client.cfg` перед изменениями.

## 1. Быстрый старт (локальный запуск сайта)

Требования: **Node.js 22 LTS**. Для облачных аккаунтов и общих счётчиков нужен **PostgreSQL 15+** (либо Docker).

```bash
# 1. Установите зависимости
npm ci

# 2. Создайте файл переменных окружения
cp -n .env.example .env
# Добавьте или отредактируйте DATABASE_URL в .env под вашу базу PostgreSQL

# 3. Примените схему таблиц PostgreSQL
npm run db:push

# 4. Запустите в режиме разработки (http://localhost:3000)
npm run dev
```

Проверка и продакшен-сборка:
```bash
npm run typecheck
npm run lint
npm run build
npm run start
```

Проверка интерфейса из Git-репозитория (Chromium, мышь и эмуляция касаний): `npx playwright install chromium`, затем `npm run test:ui`. Тесты используют локальный dev-сервер на порту 3000 или запускают его сами. База данных и внешние ключи не нужны.

Без БД можно пропустить `db:push`. Сборка, Твикер и пресеты работают без БД; для JSON и ZIP можно войти в локальный профиль. Облачные аккаунты и общие счётчики требуют БД. `/api/health` проверяет именно соединение с PostgreSQL.

**Публикация и PWA.** Приложение слушает `0.0.0.0:3000` при запуске `npm run start -- --hostname 0.0.0.0 --port 3000`. По умолчанию браузер использует текущий домен и пути `/api/...`. При необходимости задайте `VITE_API_BASE_URL=/backend` **до** `npm run build`: запросы к `/backend/api/...` Next перенаправит внутри приложения. Для нестандартного абсолютного URL нужен прокси с тем же origin, если используются аккаунты и ADMIN. Канонический callback Google всегда `/api/auth/google/callback`. `NEXT_PUBLIC_SITE_URL` задаёт публичный адрес для метаданных. При смене этих переменных пересоберите сайт.

На HTTPS браузеры с поддержкой PWA могут установить RustFlow из меню браузера. Манифест `/manifest.json` и иконки 192/512 px уже включены; `/manifest.webmanifest` — совместимый адрес. Service worker не кэширует аккаунты, чат или ADMIN: без сети работают закэшированные страницы и локальные данные, не облачные функции.

## 2. Запуск через Docker Compose

Замените пароль в секциях `db` и `web` файла `docker-compose.yml`. При первом запуске или обновлении схемы:

```bash
docker compose up -d --build
docker compose exec web npm run db:push
```

Сайт будет доступен на `http://localhost:3000`; PostgreSQL 16 хранит данные в томе `pgdata`. Перед обновлением существующей базы сделайте бэкап. Для самостоятельного хостинга без Compose выполните `npm run db:push` с рабочим `DATABASE_URL` из `.env` или окружения сервера. Регистрация начнёт работать после создания таблиц.

### Вход и регистрация

В профиле доступны вход и регистрация по логину или email (пароль — от 4 символов; для публичного аккаунта используйте длинный уникальный пароль). С PostgreSQL сервер хранит bcrypt-хеши и выдаёт 14-дневную HttpOnly-сессию. Старые scrypt-хеши обновляются после успешного входа. На публичном сайте требуется HTTPS; совместимые браузеры внутри HTTPS-iframe используют отдельную partitioned-сессию.

Без БД первый вход с новым непустым логином и паролем создаёт профиль устройства. Для существующего логина проверяется сохранённый bcrypt-хеш, открытый пароль не хранится. Форма также поддерживает локальный профиль при заблокированных cookie. Когда хранилище заблокировано, такой профиль действует до перезагрузки вкладки. Он не синхронизируется и не даёт облачных прав.

На доверенном обратном прокси **перезаписывайте** `X-Forwarded-Host`, `X-Forwarded-Proto` и `X-Forwarded-For` значениями публичного хоста, схемы и клиентского адреса; не принимайте их как есть от браузера. Ограничения входа/регистрации внутри приложения действуют в пределах процесса; для публичного запуска настройте лимиты и на прокси. Аккаунт не даёт бейдж `ADMIN`: для него по-прежнему нужна отдельная активация.

### Подключение Google

1. В Google Cloud настройте экран согласия и создайте OAuth-клиент типа **Web application**. Пока приложение в режиме тестирования, добавьте нужные тестовые аккаунты.
2. Добавьте точный *Authorized redirect URI*: `https://ваш-домен/api/auth/google/callback`. Для локального запуска — `http://localhost:3000/api/auth/google/callback`. Хост, схема и порт должны совпадать с адресом, на котором открывают RustFlow (без завершающего слеша).
3. В серверном `.env` или окружении задайте `GOOGLE_CLIENT_ID` и `GOOGLE_CLIENT_SECRET`. Старый `VITE_GOOGLE_CLIENT_ID` поддерживается как резервное имя. Для боевого домена задайте `GOOGLE_REDIRECT_URI` равным точному URI из шага 2. Перезапустите сайт (`docker compose up -d web` для Compose).

Серверу нужен доступ к `oauth2.googleapis.com` и `www.googleapis.com`. Без настроенного OAuth кнопка помечена «Демо» и открывает отдельный профиль устройства без пароля. Это не авторизация Google: ни подтверждённого email, ни облачной сессии, ни серверных прав он не получает. При успешном входе сервис показывает имя и аватар Google, если он есть. Google-профиль не объединяется автоматически с парольным даже при совпадении email. Google открывает выбор аккаунта в отдельной вкладке при работе внутри iframe, а сессия Google остаётся в открытом сайте; для отдельного профиля внутри iframe используйте пароль.

### Подключение Steam и синхронизация

1. Заполните `DATABASE_URL`, сделайте резервную копию БД и выполните `npm run db:push` для добавления `steam_sub` и `favorites`.
2. Установите `NEXT_PUBLIC_SITE_URL` в публичный HTTPS origin (например, `https://example.com`) **на этапе сборки и запуска** и `STEAM_API_KEY` в серверном окружении. Локально допустим `http://localhost:3000`. Зарегистрируйте ключ Steam Web API в своём аккаунте Steam. Серверу нужен доступ к `steamcommunity.com` и `api.steampowered.com`.
3. Кнопка Steam открывает OpenID Valve. Сервер проверяет подписанный ответ у Steam, состояние и адрес возврата; имя загружается отдельно через Steam Web API. Google и Steam — разные аккаунты и не объединяются автоматически.

Приложение использует существующие серверные сессии и собственные маршруты `/api/auth/google` и `/api/auth/steam`, **не NextAuth.js**; переход на другую систему сессий требует отдельной миграции существующих аккаунтов. Активную сборку можно привязать к аккаунту в профиле; другие сборки остаются на устройстве. Для избранных твиков и пресетов в профиле доступны отдельные кнопки сохранения в аккаунт и восстановления из него. Направление выбирается вручную, чтобы не перезаписать изменения другого устройства. Автоматического объединения нет.

### Подключение RustFlow Assistant

Без настроек чат покажет дружелюбный статус и ссылку на «Сборку», без служебных подробностей. Кнопка с примером вопроса сразу заполняет поле и отправляет этот вопрос. На сервере скопируйте `.env.example` в `.env`, если файл ещё не создан, и заполните:

| Переменная | Значение |
|---|---|
| `AI_API_KEY` | Серверный ключ провайдера. Не добавляйте его в исходники или `NEXT_PUBLIC_*`. |
| `AI_API_BASE_URL` | `https://api.openai.com/v1` или `https://api.anthropic.com/v1`. Можно указать и полный URL конечной точки; HTTP допустим только на loopback. Нужен поток `text/event-stream`. |
| `AI_MODEL` | Например `gpt-4o-mini` или поддерживаемая модель Anthropic. |
| `AI_API_FORMAT` | `openai` или `anthropic`; для совместимых прокси выберите явно. |

Старые `RUSTFLOW_LLM_API_KEY` и `RUSTFLOW_LLM_ENDPOINT` остаются резервными именами. Для пользователя — до 400 символов в вопросе, до 450 токенов в ответе, 5 секунд между запросами, 5 запросов в час и 12 за 24 часа на IP. Для подтверждённого `ADMIN` квоты по IP не применяются, до 1500 токенов в ответе.

`RUSTFLOW_ADMIN_TOKEN` — отдельный серверный секрет. Для новой установки сгенерируйте 32 случайных байта (`openssl rand -hex 32`) и сохраните их в `.env`, не в `.env.example`, Git или `NEXT_PUBLIC_*`. Активируйте сессию на `/admin` или приватной командой в чате. Токен не отображается в сообщениях и не отправляется провайдеру; отдельная подписанная HttpOnly-сессия действует 8 часов. После пяти неудачных попыток ввод блокируется на час для этого IP. Для завершения используйте `/logout` в чате, кнопку на `/admin` или выход из профиля.

Перезапустите `npm run start` (или `npm run dev`). Для Docker: `docker compose up -d web`, чтобы контейнер получил новые серверные переменные. На прокси не буферизуйте ответы `/api/assistant` (или путь с настроенным префиксом).

Внешнему API уходят вопрос, до четырёх последних пар сообщений, параметры железа и подходящая статья базы знаний, если найдена. Имя профиля, ID владельца, JSON-бэкап и команды ADMIN не передаются. Завершённые ответы сохраняются в истории браузера и удаляются кнопкой в чате. Ограничения внутри приложения действуют только в пределах процесса. В публичном развёртывании настройте общий лимит на прокси и ограничение расходов у провайдера.

## 4. Как собрать полное Windows-приложение (`.exe`)

В папке `app-kit/` (доступна в полном архиве `RustFlow-Complete-Edition.zip`, `/api/source?download=full`) лежат все готовые файлы:
1. **`app-kit/tauri/`** — флагманское нативное приложение на **Tauri v2 + Rust** (установщик `.exe` ~8 МБ, минимум ОЗУ, автоопределение CPU/GPU/RAM/SSD, автопоиск Rust в Steam, бэкап/применение `client.cfg`, создание точки восстановления Windows, запуск `.reg`/`.bat` с UAC).
2. **`app-kit/electron/`** — альтернативная сборка `.exe` на **Electron** (только Node.js, без установки компилятора Rust).
3. **`app-kit/cloud/`** — SQL-схема с Row-Level Security, серверный роут синхронизации и `CloudStorageAdapter` для аккаунтов пользователей.
4. **`app-kit/deploy/`** — конфиг Nginx + HTTPS для своего домена на VPS.
5. **`app-kit/GUIDE-FULL-APP.md`** — подробное пошаговое руководство по сборке `.exe`, подписи кода и правилам безопасности Easy Anti-Cheat.


App Kit — исходные шаблоны, а не готовый установщик. На публичном сервере перед включением ИИ настройте лимит расходов провайдера и прокси; ключи передавайте при запуске, а не при сборке Docker-образа.

## Графические профили и безопасное применение

Все генераторы и установщики используют общий набор `src/lib/graphics-profiles.ts`. Комбат: дальность 1200, shader LOD 200, минимальные вода, трава и частицы. Баланс: дальность 1600 и shader LOD 300. Качество: дальность 2200 и shader LOD 400; Potato: дальность 800 и масштаб рендера 85%. Качество и Реалистичность повышают детализацию. `gc.buffer`: 2048 при 16 ГБ, 4096 при 32+ ГБ; пользователь может выбрать значение вручную. Эти настройки не гарантируют прирост: сравнивайте средний FPS и 1% low в одной сцене.

На основании [справочника команд сообщества](https://github.com/QuietusPlus/Rust-Easy_Config/blob/41eecd2d41cd36048e1c3e9eee1cf19c73b0e6cf/docs/Rust-Variables.md) используем `grass.displace`, а не `grass.displacement`. В том же источнике `graphics.shadowdistance` имеет минимум 50, а отключение теней `graphics.shadowmode 0` отмечено как устаревшее; Комбат использует 50 и режим 1. Команды `graphics.water` и `grass.on` не включены из-за недостаточного подтверждения. Это не официальная гарантия Facepunch: диапазоны могут измениться, проверьте команды в F1 на своей версии Rust.

До записи закройте игру и сохраните оригинал `Rust/cfg/client.cfg`. Скачанный файл содержит только предлагаемые настройки: не заменяйте им весь оригинал, а перенесите строки по одной. ZIP содержит скрипт восстановления именованной резервной копии. Установщик твика просит подтверждение и создаёт копию при первом применении; она не заменяется при следующих запусках. Настольная оболочка создаёт отдельный снимок перед применением.


### Безопасное обновление существующего конфига

В «Мастерской» доступен инструмент для чтения исходного UTF-8 `client.cfg`, скачивания `client.cfg.bak` и подготовки файла с точечными изменениями графики. Браузер не может самостоятельно создать файл рядом с игрой: сохраните резервную копию и замените файл вручную только после проверки и закрытия Rust. FOV, управление, звук, HUD, сеть, GC и лимит FPS не меняются при слиянии. Настольная Tauri-версия сохраняет снимок; новый JavaFX-прототип — в `desktop-java/README.md`.
